# 健康评估功能 - 面试提问问题清单

## 一、业务理解类

### Q1: 请介绍一下健康评估功能的业务背景和核心价值？
**考察点**：业务理解、价值认知
**参考答案要点**：
- 对老人体检报告进行智能分析，评估身体健康状态
- 响应时间从人工8秒降低到AI分析1秒
- 护理人员使用效率提升约30%
- 自动生成健康评分、风险等级、护理等级建议

### Q2: 健康评分是如何映射到护理等级的？设计思路是什么？
**考察点**：业务规则、设计思路
**参考答案要点**：
- 分数越高，健康状况越好，护理等级越低
- 90+ → 四级护理（最轻）
- 80-90 → 三级护理
- 70-80 → 二级护理
- 60-70 → 一级护理
- 60以下 → 特级护理（最重）

## 二、技术实现类

### Q3: 为什么选择百度千帆大模型？有什么优势？
**考察点**：技术选型、成本意识
**参考答案要点**：
- 成本考虑：提供免费额度，适合项目初期
- 中文优化：针对中文场景优化，体检报告分析更准确
- OpenAI兼容：使用标准SDK，后续可无缝切换
- 合规性：国内服务商，数据不出境

### Q4: Redis缓存体检报告内容的作用是什么？为什么设置24小时过期？
**考察点**：缓存设计、资源管理
**参考答案要点**：
- 避免重复解析PDF（耗时2-3秒）
- 用户上传后可能不会立即评估
- 24小时平衡用户体验和资源消耗
- 用户通常当天完成评估

### Q5: Redis存储体检报告为什么用Hash结构？Key和Field分别是什么？
**考察点**：Redis数据结构、设计细节
**参考答案要点**：
- Key: "healthReport"（固定值）
- Field: 身份证号
- Value: PDF文本内容
- Hash优势：一个Key管理所有用户报告，通过Field快速定位

### Q6: PDF解析使用了什么技术？有什么局限性？
**考察点**：技术细节、问题认知
**参考答案要点**：
- 使用Apache PDFBox解析PDF
- PDFTextStripper提取文本内容
- 局限性：只能提取文本，无法识别图片、表格
- 扫描件PDF无法处理（需OCR技术）

## 三、深度追问类

### Q7: Prompt提示词是如何设计的？为什么要明确要求输出JSON格式？
**考察点**：AI应用能力、Prompt工程
**参考答案要点**：
- 分步骤要求：总检日期 → 风险评估 → 异常分析 → 系统评分 → 总结
- 明确输出格式为纯JSON，便于程序解析
- 以专业医生视角分析，提高准确性
- 结构化输出便于后续处理和存储

### Q8: 如何保证AI分析结果的准确性？
**考察点**：质量控制、业务保障
**参考答案要点**：
- Prompt工程：详细的提示词设计
- 结构化输出：要求AI返回JSON
- 人工审核：关键决策仍需人工确认
- 持续优化：根据反馈调整Prompt

### Q9: Redis缓存失效了怎么办？
**考察点**：异常处理、用户体验
**参考答案要点**：
- 代码中检查缓存是否存在
- 不存在时抛出友好异常提示用户重新上传
- 记录日志便于排查Redis问题
- 可考虑持久化到数据库作为备份

### Q10: 如何防止用户重复提交评估请求？
**考察点**：幂等性设计、安全意识
**参考答案要点**：
- 前端防抖：提交按钮禁用
- 后端幂等性：基于身份证号+日期判断是否已评估
- Redis分布式锁：防止并发提交
