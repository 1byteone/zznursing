# 智颐养老系统-项目复盘笔记（贴代码版）

> 这份笔记只做一件事：**把“项目怎么讲”绑定到仓库里的真实代码**。  
> 不空谈概念，不虚构 SSE / 微服务 / 多智能体，只围绕当前项目已经实现的类、方法、调用链来复盘。

---

## 1. 先用代码定义这个项目是什么

从根目录 `pom.xml` 可以看出这是一个典型的多模块单体项目，核心模块包括：

- `zzyl-admin`：后台启动入口
- `zzyl-framework`：拦截器、Redis 配置、认证相关能力
- `zzyl-common`：通用工具、常量、AI 调用封装
- `zzyl-nursing-platform`：养老业务核心模块
- `zzyl-quartz`：定时任务
- `zzyl-ui`：后台前端

如果面试官问“你的项目整体是什么架构”，比较稳的回答是：

> 这是一个基于 `Spring Boot + MyBatis-Plus + Redis + MySQL` 的多模块单体项目，养老业务主要集中在 `zzyl-nursing-platform`，框架能力沉到 `zzyl-framework` 和 `zzyl-common`。项目不是微服务，但已经接入了 AI、微信和 IoT 三类外部能力。

---

## 2. 代码里最值得讲的四条主链路

当前项目最能体现深度的，不是普通 CRUD，而是下面四条链路：

1. **健康评估链路**：PDF 报告上传 → PDF 解析 → Redis 暂存 → AI 分析 → 结构化落库
2. **小程序登录链路**：微信 `code` 换 `openid` → 获取手机号 → 自动注册/更新 → JWT → `ThreadLocal`
3. **IoT 设备链路**：产品同步 → 设备注册 → 查询设备影子 → AMQP 接收设备上报数据
4. **入住办理链路**：校验老人状态 → 更新床位 → 保存老人 → 创建合同 → 写入住记录/入住配置

下面按代码展开。

## 3. 健康评估模块：这是项目里最适合重点讲的部分

## 3.1 入口 Controller 在哪

健康评估的入口在：

- `zzyl-nursing-platform/src/main/java/com/zzyl/nursing/controller/HealthAssessmentController.java`

关键方法有两个：

- `uploadFile()`：`HealthAssessmentController.java:55`
- `add()` 中调用 `healthAssessmentService.insertHealthAssessment(...)`：`HealthAssessmentController.java:129`

也就是说，这个模块在代码层面其实分成了两个动作：

1. 先上传体检报告
2. 再提交健康评估业务数据

这个拆分是很适合面试讲的，因为它体现了**“文件预处理”和“业务提交”分阶段设计**。

## 3.2 先看上传阶段代码到底做了什么

`HealthAssessmentController#uploadFile` 的核心逻辑非常清晰：

```java
String url = aliyunOSSOperator.upload(file.getBytes(), file.getOriginalFilename());
String content = PDFUtil.pdfToString(file.getInputStream());
redisTemplate.opsForHash().put("healthReport", idCardNo, content);
redisTemplate.expire("healthReport", 24, TimeUnit.HOURS);
```

对应位置：

- OSS 上传：`HealthAssessmentController.java:61`
- PDF 转文本：`HealthAssessmentController.java:69`
- Redis Hash 暂存：`HealthAssessmentController.java:71`
- 过期时间 24 小时：`HealthAssessmentController.java:74`

### 这段代码面试怎么讲

这段代码能说明三件事：

#### 第一，项目不是“前端直接传字符串给 AI”

而是先把 PDF 做服务端解析，这样 AI 输入是可控的文本，不受前端能力限制。

#### 第二，项目用了“中间态缓存”

上传报告和提交评估不是一个 HTTP 请求完成，而是：

- 上传时完成文件解析
- 提交时根据身份证号去 Redis 取中间结果

这比“每次提交都重新解析 PDF”更合理。

#### 第三，Redis 的使用场景很具体

这里不是泛泛地说“用了 Redis 缓存”，而是：

- Key：`healthReport`
- Field：`idCardNo`
- Value：PDF 解析后的文本
- TTL：`24h`

这是很典型的“业务中间数据短期缓存”。

也就是说，你要强调的是**“结构化接入”**，而不是“模型很聪明”。

## 3.4 `getPrompt()` 为什么是这个模块的核心

`getPrompt(...)` 在 `HealthAssessmentServiceImpl.java:160`，它不是一句简单提示词，而是把整个业务需求翻译成模型输入协议。

代码里做了两步关键校验：

```java

```

对应位置：

> 我没有让模型自由输出自然语言，而是通过 `getPrompt()` 把输出字段固定下来，再用 `HealthReportVo` 去接结果。这样前端展示、数据库存储、后续统计都更稳定。

## 4.4 为什么这个项目可以讲 ThreadLocal，而不是只说 JWT

真正体现工程意识的地方在：

- `zzyl-framework/src/main/java/com/zzyl/framework/interceptor/MemberInterceptor.java`

关键方法：

- `preHandle(...)`：`MemberInterceptor.java:26`
- `afterCompletion(...)`：`MemberInterceptor.java:63`

核心逻辑如下：

```java
String token = request.getHeader("authorization");
Claims claims = tokenService.parseToken(token);
Long userId = MapUtil.get(claims, "userId", Long.class);
UserThreadLocal.set(userId);
```

结束时：

```java
UserThreadLocal.remove();
```

### 这段代码怎么讲

如果你只说“我用了 JWT”，其实比较普通。  
但如果你能讲到 `MemberInterceptor + UserThreadLocal`，层次会明显高一些：

> 登录成功后返回 JWT，后续请求进入 `/member/**` 接口时，会被 `MemberInterceptor` 拦截。拦截器会从请求头解析 token，把 `userId` 放入 `UserThreadLocal`，业务代码就能直接获取当前家属 ID。请求结束时再在 `afterCompletion()` 里做 `remove()`，避免线程复用带来的脏数据问题。

## 4.5 `/member/**` 为什么会被这个拦截器拦住

配置在：

- `zzyl-framework/src/main/java/com/zzyl/framework/config/ResourcesConfig.java`

关键代码：

```java
registry.addInterceptor(memberInterceptor)
        .excludePathPatterns(EXCLUDE_PATH_PATTERNS)
        .addPathPatterns("/member/**");
```

对应位置：

- `ResourcesConfig.java:59`

排除项里还有：

- `/member/user/login`
- `/member/roomTypes`

这能说明你理解的是**接口级认证边界**，而不是“系统全局一把梭”。

## 4.6 小程序登录模块怎么总结

> 小程序登录入口在 `FamilyMemberController#login`，主流程在 `FamilyMemberServiceImpl#login`。系统先通过 `WechatServiceImpl#getOpenid` 用 code 换 openid，再通过 `getPhone` 获取手机号，如果本地没有用户就自动注册，有则更新手机号。最后用 `TokenService#createToken` 生成 JWT。后续 `/member/**` 请求会被 `MemberInterceptor` 拦截，把 token 里的 `userId` 写入 `UserThreadLocal`，业务层直接取当前用户即可。

## 5.5 真正有深度的是 AMQP 消费链路

设备数据接入不止“查接口”，还包括异步接收上报消息。代码在：

- `zzyl-nursing-platform/src/main/java/com/zzyl/nursing/job/AmqpClient.java`

关键点：

- 类实现了 `ApplicationRunner`：`AmqpClient.java:37`
- 启动后自动执行 `start()`：`AmqpClient.java:58`
- 收到消息后交给线程池：`AmqpClient.java:176`
- 真正处理消息的方法是 `processMessage(...)`：`AmqpClient.java:188`

这里最值得讲的两段代码：

```java
consumer.setMessageListener(messageListener);
```

和：

```java
executorService.submit(() -> processMessage(message));
```

### 为什么这里是亮点

因为这说明系统已经形成了完整的设备数据回流链路：

1. 设备数据先上报到华为云 IoTDA
2. 本系统通过 AMQP 订阅消息
3. 收到消息后异步线程池处理
4. 再交给 `deviceDataService.batchInsertDeviceData(...)` 落库

关键落点：

- 调用批量入库：`AmqpClient.java:216`

### 这里面试非常推荐这样讲

> IoT 模块里我觉得最有价值的不是设备 CRUD，而是 `AmqpClient` 这条数据回流链路。系统启动后会订阅 IoT 平台消息，收到上报数据后不在回调线程里直接做重逻辑，而是先提交到线程池，再解析 `notify_data` 并批量入库，这样接入链路更稳定。

`CheckInServiceImpl#apply` 的链路很完整：

Elder elder = elderMapper.selectOne(...);

## 10. 最后给你一版“贴代码”的 1 分钟口述稿

> 这是一个养老院综合管理系统，核心业务代码在 `zzyl-nursing-platform`。我主要做了三个比较有代表性的模块。  
> 第一是健康评估，在 `HealthAssessmentController#uploadFile` 里先把体检 PDF 上传 OSS 并解析成文本，再把解析结果按身份证号缓存到 Redis；提交评估时，`HealthAssessmentServiceImpl#insertHealthAssessment` 会通过 `getPrompt()` 取出报告内容，调用 `AIModelInvoker#qianfanInvoker` 做结构化分析，最后把健康分、风险等级、护理等级建议等结果落库。  
> 第二是小程序登录，在 `FamilyMemberServiceImpl#login` 里通过微信 `code` 获取 `openid` 和手机号，完成家属自动注册/更新，再生成 JWT；后续 `/member/**` 请求由 `MemberInterceptor` 解析 token，并把 `userId` 放到 `UserThreadLocal`。  
> 第三是 IoT 模块，在 `DeviceServiceImpl` 里做了产品同步、设备注册和设备影子查询，同时系统启动后会通过 `AmqpClient` 订阅设备消息，异步消费上报数据并落库。  
> 这个项目虽然不是微服务，但业务链路完整，AI、微信和 IoT 都真正接进了业务代码里。
