> 本笔记用于Java后端面试项目经历复盘，通过代码思维链快速熟悉和回顾健康评估功能的业务实现。

## 一、功能概述

### 1.1 业务背景
在养老院管理系统中，需要对老人的体检报告进行智能分析，评估老人的身体健康状态并给出健康建议。传统人工分析体检报告耗时长、效率低，因此开发了基于AI大模型的智能健康评估功能。

### 1.2 核心价值
- **响应时间优化**：从人工分析的8秒降低到AI分析的1秒
- **效率提升**：护理人员使用效率提升约30%
- **智能化决策**：自动生成健康评分、风险等级、护理等级建议

### 1.3 技术栈
| 技术 | 用途 |
|------|------|
| 百度千帆AI大模型 | 体检报告智能分析 |
| Redis | 缓存体检报告内容，提高响应速度 |
| PDFBox | PDF文件解析 |
| 阿里云OSS | 体检报告文件存储 |
| MyBatis-Plus | 数据持久层 |
| Spring Boot | 后端框架 |

## 二、核心业务流程

### 2.1 整体流程图

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  上传体检报告   │───>│  Redis缓存内容  │───>│  提交评估请求   │
│   (PDF文件)     │    │  (24小时有效)   │    │  (身份证号)     │
└─────────────────┘    └─────────────────┘    └─────────────────┘
                                                      │
                                                      ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  保存评估结果   │<───│  解析JSON响应   │<───│  调用千帆大模型 │
│   (MySQL)       │    │  (FastJSON)     │    │  (AI分析)       │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### 2.2 详细流程说明

#### 步骤1：上传体检报告
```
前端上传PDF文件 + 身份证号
    ↓
Controller接收请求
    ↓
1. 上传文件到阿里云OSS，获取URL
2. 使用PDFBox解析PDF内容为文本
3. 将文本内容存入Redis Hash结构
   - Key: "healthReport"
   - Field: 身份证号
   - Value: PDF文本内容
4. 设置24小时过期时间
```

#### 步骤2：提交评估请求
```
前端提交老人信息（姓名、身份证号）
    ↓
Service层处理
    ↓
1. 从Redis获取缓存的体检报告内容
2. 构建Prompt提示词
3. 调用百度千帆AI大模型
4. 解析AI返回的JSON结果
5. 保存评估数据到数据库
```

## 三、核心代码实现

### 3.1 Controller层 - 上传体检报告

**文件路径**：`zzyl-nursing-platform/src/main/java/com/zzyl/nursing/controller/HealthAssessmentController.java`

```java
@ApiOperation("上传体检报告")
@PostMapping("/upload")
public AjaxResult uploadFile(@RequestPart("file") MultipartFile file,
                             @RequestPart(value = "idCard") String idCardNo) {
    try {
        // 1. 上传到阿里云OSS
        String url = aliyunOSSOperator.upload(file.getBytes(), file.getOriginalFilename());

        // 2. PDF文件内容读取为字符串
        String content = PDFUtil.pdfToString(file.getInputStream());

        // 3. 临时存储到Redis中（Hash结构）
        redisTemplate.opsForHash().put("healthReport", idCardNo, content);

        // 4. 设置24小时过期时间
        redisTemplate.expire("healthReport", 24, TimeUnit.HOURS);

        return AjaxResult.success().put("url", url);
    } catch (Exception e) {
        return AjaxResult.error(e.getMessage());
    }
}
```

**面试要点**：
- 使用`@RequestPart`接收文件和表单数据
- Redis Hash结构存储：Key为固定值，Field为身份证号，Value为报告内容
- 设置过期时间防止Redis内存溢出

### 3.3 Prompt提示词设计

```java
private String getPrompt(String idCard) {
    // 从Redis获取体检报告内容
    String content = (String) redisTemplate.opsForHash().get("healthReport", idCard);

    if (StringUtils.isEmpty(content)) {
        throw new BaseException("未找到体检报告，请先上传PDF报告");
    }

    // 构建Prompt
    String prompt = "请以一个专业医生的视角来分析这份体检报告...\n" +
            "体检内容如下：\n" + content + "\n" +
            "要求：\n" +
            "1. 提取体检报告中的"总检日期"；\n" +
            "2. 给出风险等级和健康指数...\n" +
            "3. 风险等级占比分析...\n" +
            "4. 异常数据详细解读...\n" +
            "5. 八大系统评分...\n" +
            "6. 综合总结...\n" +
            "输出要求：纯JSON格式...";

    return prompt;
}
```

**面试要点**：
- Prompt工程的重要性：明确输出格式（JSON）
- 分步骤要求：总检日期 → 风险评估 → 异常分析 → 系统评分 → 总结
- 错误处理：Redis中不存在时的友好提示

### 3.4 AI模型调用

**文件路径**：`zzyl-common/src/main/java/com/zzyl/common/ai/AIModelInvoker.java`

```java
@Component
public class AIModelInvoker {
    @Autowired
    private BaiduAIProperties baiduAIProperties;

    public String qianfanInvoker(String prompt) {
        // 创建OpenAI兼容客户端
        OpenAIClient client = OpenAIOkHttpClient.builder()
                .apiKey(baiduAIProperties.getApiKey())
                .baseUrl(baiduAIProperties.getBaseUrl())
                .build();

        // 构建请求参数
        ChatCompletionCreateParams params = ChatCompletionCreateParams.builder()
                .addUserMessage(prompt)
                .model(baiduAIProperties.getModel())
                .responseFormat(ChatCompletionCreateParams.ResponseFormat.ofJsonObject(
                    ResponseFormatJsonObject.builder().build()))
                .build();

        // 调用API并返回结果
        ChatCompletion chatCompletion = client.chat().completions().create(params);
        return chatCompletion.choices().get(0).message().content().orElseGet(() -> "");
    }
}
```

**面试要点**：
- 百度千帆兼容OpenAI SDK，降低学习成本
- `responseFormat`设置为JSON，确保输出格式
- 配置外部化：API Key、Base URL、Model从配置文件读取

### 3.5 PDF解析工具

**文件路径**：`zzyl-common/src/main/java/com/zzyl/common/utils/PDFUtil.java`

```java
public class PDFUtil {
    public static String pdfToString(InputStream inputStream) {
        PDDocument document = null;
        try {
            // 加载PDF文档
            document = PDDocument.load(inputStream);

            // 创建PDFTextStripper提取文本
            PDFTextStripper pdfStripper = new PDFTextStripper();

            // 提取文本内容
            String text = pdfStripper.getText(document);
            return text;
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (document != null) {
                document.close();
                inputStream.close();
            }
        }
        return null;
    }
}
```

**面试要点**：
- 使用Apache PDFBox解析PDF
- 注意资源释放（finally块关闭流）
- 局限性：只能提取文本，无法识别图片、表格等复杂结构

## 五、Redis缓存策略

### 5.1 为什么使用Redis缓存？

**问题场景**：
1. 用户上传PDF后，可能不会立即提交评估
2. PDF解析耗时（IO操作）
3. AI分析耗时（网络请求）

**解决方案**：
```
上传时：解析PDF → 存入Redis（24小时有效）
评估时：从Redis读取 → 直接调用AI
```

### 5.2 Redis数据结构选择

使用**Hash结构**：
```
Key: "healthReport"
Field: 身份证号（如"330103199001011234"）
Value: PDF文本内容
```

**优势**：
- 一个Key管理所有用户的报告
- 通过Field快速定位特定用户的报告
- 方便批量管理（如批量清理过期数据）

### 5.3 过期策略

```java
// 设置24小时过期
redisTemplate.expire("healthReport", 24, TimeUnit.HOURS);
```

**为什么是24小时？**
- 用户通常当天完成评估
- 避免长期占用Redis内存
- 平衡用户体验和资源消耗

## 七、面试常见问题

### Q1：为什么选择百度千帆而不是其他AI模型？

**参考回答**：
1. **成本考虑**：千帆提供免费额度，适合项目初期
2. **中文优化**：针对中文场景优化，体检报告分析更准确
3. **OpenAI兼容**：使用标准SDK，后续可无缝切换其他模型
4. **合规性**：国内服务商，数据不出境，符合养老行业合规要求

### Q2：Redis缓存失效怎么办？

**参考回答**：
```java
// 代码中的处理
if (StringUtils.isEmpty(content)) {
    log.error("从Redis中未获取到身份证号[{}]的体检报告内容", idCard);
    throw new BaseException("未找到体检报告，请先上传PDF报告后再提交");
}
```

**改进方案**：
1. 提示用户重新上传
2. 记录日志，排查Redis问题
3. 可考虑持久化到数据库作为备份

### Q3：如何保证AI分析结果的准确性？

**参考回答**：
1. **Prompt工程**：详细的提示词设计，明确输出格式
2. **结构化输出**：要求AI返回JSON，便于解析和验证
3. **人工审核**：关键决策（如护理等级）仍需人工确认
4. **持续优化**：根据实际使用反馈调整Prompt

### Q4：PDF解析有哪些局限性？

**参考回答**：
1. **纯文本提取**：无法识别图片、表格等复杂结构
2. **格式依赖**：依赖PDF的文本层，扫描件无法处理
3. **编码问题**：特殊字符可能解析失败

**改进方案**：
- 使用OCR技术处理扫描件
- 使用PDF表格解析库处理表格数据

### Q5：如何处理大文件上传？

**参考回答**：
```yaml
# application.yml配置
spring:
  servlet:
    multipart:
      max-file-size: 10MB      # 单个文件大小限制
      max-request-size: 20MB   # 总上传大小限制
```

**优化方案**：
1. 前端压缩PDF
2. 分片上传
3. 异步处理

### Q6：如何防止重复提交？

**参考回答**：
1. **前端防抖**：提交按钮禁用
2. **后端幂等性**：基于身份证号+日期判断是否已评估
3. **Redis分布式锁**：防止并发提交

### Q7：健康评分如何映射到护理等级？

**参考回答**：
```java
private String getLevelNameByHealthScore(double healthScore) {
    if (healthScore >= 90) {
        return "四级护理等级";  // 最轻
    } else if (healthScore >= 80) {
        return "三级护理等级";
    } else if (healthScore >= 70) {
        return "二级护理等级";
    } else if (healthScore >= 60) {
        return "一级护理等级";
    } else {
        return "特级护理等级";  // 最重
    }
}
```

**设计思路**：
- 分数越高，健康状况越好，护理等级越低
- 60分为分界线，低于60分建议特级护理
