## 1. 2 分钟版口述稿

面试时如果对方说“你介绍一下项目”，可以直接按下面这套说。

### 2 分钟标准稿

智颐养老系统是一个面向养老院场景的综合管理平台，分为后台管理端和家属小程序端。  
后台主要负责老人入住、护理等级、护理计划、合同、健康评估和设备管理；小程序端主要给家属做微信登录、预约和信息查询。  
整个项目技术栈是 `Spring Boot + MyBatis-Plus + MySQL + Redis`，同时接入了微信开放平台、百度千帆和华为云 IoTDA。

我在这个项目里主要参与了三个比较有代表性的模块。

第一个是**健康评估模块**。  
这部分的业务场景是老人入住前需要上传体检报告，系统自动给出健康分、风险等级和护理建议。  
代码上是先在 `HealthAssessmentController#uploadFile` 里把 PDF 上传到 OSS，再用 `PDFUtil` 解析成文本，并按身份证号暂存到 Redis。  
提交评估时，`HealthAssessmentServiceImpl#insertHealthAssessment` 会根据身份证号取出报告内容，拼接 Prompt，调用 `AIModelInvoker#qianfanInvoker` 请求百度千帆，最后把返回的 JSON 解析成对象，再映射成健康分、风险等级、是否建议入住和推荐护理等级等字段落库。  
这个模块我觉得最有价值的点，不是“调了 AI”，而是把 AI 输出变成了业务系统能稳定接住的结构化数据。

第二个是**微信小程序登录模块**。  
这部分是在 `FamilyMemberServiceImpl#login` 里实现的，整体链路是：前端传微信 `code` 过来，后端通过 `WechatServiceImpl#getOpenid` 获取 `openid`，再获取手机号；如果本地没有家属账号就自动注册，有的话就更新手机号，然后生成 JWT 返回前端。  
后续 `/member/**` 接口会被 `MemberInterceptor` 拦截，从 token 中取出 `userId` 写入 `UserThreadLocal`，这样业务代码就能直接拿当前登录用户。  
这里我会重点强调一点，就是 `afterCompletion()` 里做了 `remove()`，避免线程复用导致 ThreadLocal 脏数据。

第三个是**IoT 设备接入模块**。  
设备管理在 `DeviceServiceImpl` 里，支持同步产品列表、注册设备、查询设备影子属性。  
比如注册设备时，不是直接调云平台接口，而是先校验设备名称、节点号和绑定位置，防止业务冲突，再调用华为云 IoTDA 创建设备，并把云端 `deviceId` 和本地绑定关系一起保存。  
另外系统启动后会通过 `AmqpClient` 订阅 IoT 消息，异步接收设备上报数据并落库，这也是项目里比较有技术辨识度的一条链路。

整体来说，这个项目虽然不是微服务，但业务链路比较完整，我主要做的是把 AI、微信和 IoT 这三类外部能力真正稳定地接进业务系统。

## 3. 5 分钟版口述稿

如果面试官听完你的 2 分钟版本之后继续问“你展开说说”，就接下面这套。

### 5 分钟标准稿

这个项目叫智颐养老系统，主要服务养老院场景，分为后台管理端和家属小程序端。  
后台负责老人入住、护理等级、护理计划、合同、健康评估和设备管理，小程序端负责家属的微信登录、预约和信息查询。  
从代码结构来看，它是一个多模块单体项目，养老业务主要集中在 `zzyl-nursing-platform`，认证和 Redis 等通用能力在 `zzyl-framework` 和 `zzyl-common`。

我在项目里做得比较深的模块主要有三个：健康评估、小程序登录和 IoT 设备接入。另外也参与了入住办理这条业务链路。

先说**健康评估模块**。  
这个模块的业务背景是养老院在老人入住前需要参考体检报告做健康判断，但人工解读效率低，而且标准不统一，所以我们做了一个 AI 辅助评估流程。  
从代码看，这条链路分成两个阶段。

第一个阶段是上传体检报告。  
在 `HealthAssessmentController#uploadFile` 里，系统先把 PDF 上传到 OSS，然后用 `PDFUtil.pdfToString()` 把 PDF 解析成文本，最后把文本按身份证号写入 Redis Hash，Key 是 `healthReport`，过期时间 24 小时。  
这里的设计点是把“文件上传”和“AI 评估提交”拆开，中间结果放 Redis，而不是每次都重新解析 PDF。

第二个阶段是提交评估。  
在 `HealthAssessmentServiceImpl#insertHealthAssessment` 里，系统先通过身份证号从 Redis 取出体检报告文本，再通过 `getPrompt()` 拼接 Prompt，请求 `AIModelInvoker#qianfanInvoker` 调用百度千帆。  
返回结果后，系统不是直接保存原始文本，而是先反序列化成 `HealthReportVo`，再映射为健康分、风险等级、总检日期、异常分析、系统评分、是否建议入住和推荐护理等级等字段。  
比如代码里会根据健康分判断是否建议入住，并通过 `getLevelNameByHealthScore()` 把分数映射成护理等级。  
所以这个模块真正体现的不是“会调 AI”，而是**怎么把 AI 的概率性输出变成业务上的确定性结构化结果**。  
如果面试官追问难点，我会说难点在于 Prompt 约束和业务规则拆分：AI 负责分析，后端负责确定性的规则判断。

第二个模块是**微信小程序登录**。  
这个模块的主逻辑在 `FamilyMemberServiceImpl#login`。  
整体链路是：前端把微信 `code` 和 `phoneCode` 传过来，系统先通过 `WechatServiceImpl#getOpenid` 调微信接口拿到 `openid`，再通过 `getPhone()` 获取手机号。  
然后按 `openid` 查询本地家属账号，如果没有就自动注册一个，有的话就更新手机号，最后用 `TokenService#createToken` 生成 JWT，把 `userId` 和 `nickName` 放进 claims 返回给前端。  
后续请求进入 `/member/**` 接口时，会被 `MemberInterceptor#preHandle` 拦截，拦截器从请求头里拿 `authorization`，解析 token，把 `userId` 放进 `UserThreadLocal`，这样业务代码里就能直接拿当前登录用户。  
这个模块我最想强调的其实不是 JWT，而是 `ThreadLocal` 的生命周期管理。因为线程池会复用线程，如果不清理，前一个请求的数据可能串到下一个请求，所以在 `afterCompletion()` 里做了 `UserThreadLocal.remove()`。  
这一点面试时很加分，因为它体现的是工程意识，不是只会背登录流程。

第三个模块是**IoT 设备接入**。  
这部分的业务场景是养老院会接入一些智能手环、床垫、定位设备等，系统既要做设备管理，也要接住设备上报数据。  
代码主要在 `DeviceServiceImpl` 和 `AmqpClient`。

先说设备管理。  
在 `DeviceServiceImpl#syncProductList` 里，系统会调用华为云 IoTDA 的产品列表接口，然后把产品元数据同步到 Redis，Key 是 `iot:all_product_list`。  
这样做的原因是设备产品列表变化频率低，但查询频率高，没必要每次页面展示都走远程接口。

再说设备注册。  
`DeviceServiceImpl#registerDevice` 不是直接调云接口，而是先做了三层校验：设备名称不能重复、节点号不能重复、同一位置不能重复绑定同一产品。  
校验通过后才调用 IoTDA 创建设备，并把云端 `deviceId`、本地绑定位置、产品信息和密钥一起保存。  
这里能体现出一个点：我关注的不是“云上有设备”，而是“设备怎么和本地业务模型绑定起来”。

IoT 这部分更有深度的其实是消息回流。  
系统启动后，`AmqpClient` 作为 `ApplicationRunner` 会自动拉起 AMQP 订阅。  
收到设备消息后，不会在消息回调线程里直接做重逻辑，而是先通过 `executorService.submit()` 交给线程池，再在 `processMessage()` 里解析 `notify_data`，最后调用 `deviceDataService.batchInsertDeviceData(...)` 批量入库。  
这个设计能体现出我对异步消费场景的理解：消息接收线程要尽量轻，业务处理异步化，避免拖慢消费吞吐。

除了这三个模块，我还参与了**入住办理链路**。  
在 `CheckInServiceImpl#apply` 里，这条链路会先校验老人是否已入住，再更新床位状态，然后保存或更新老人档案，生成合同编号，写合同、写入住记录、写入住配置。  
所以这部分我更愿意把它讲成“多表业务状态流转”，而不是简单 CRUD。  
另外合同状态还会通过 `ContractTask -> ContractServiceImpl#updateContractStatus` 定时推进，这体现了系统里除了用户触发流程，还有时间驱动型业务状态变化。

如果让我总结这个项目的价值，我会说它不是一个特别重架构的项目，但它很适合体现三个能力：

1. **业务理解能力**：老人入住、护理、合同、健康评估这些链路是打通的  
2. **第三方能力接入能力**：接了微信、百度千帆、华为云 IoTDA  
3. **工程落地能力**：不仅调通接口，还把 AI、认证、缓存、异步消费真正接进了现有业务代码

## 5. 面试时的节奏控制

## 5.1 如果面试官只给你 1~2 分钟

只说：

- 项目定位
- 你负责的 3 个模块
- 每个模块一句亮点

不要展开：

- 具体字段
- 过多类名
- 太长代码细节

## 5.2 如果面试官愿意听你讲 5 分钟

优先展开顺序建议：

1. 健康评估
2. 小程序登录
3. IoT
4. 入住办理

原因：

- 健康评估最能拉开差距
- 登录模块最容易被继续追问
- IoT 模块最有辨识度
- 入住办理适合补“业务复杂度”

## 6. 面试时可以主动补的两句加分话

### 句子一：强调你不是只会调接口

> 我在这个项目里不是只把第三方接口调通，而是重点关注这些能力怎么稳定接入现有业务，比如 AI 输出怎么结构化落库、IoT 数据怎么异步回流、登录态怎么在业务层方便拿到当前用户。

### 句子二：强调你的工程意识

> 我比较在意边界问题，比如 ThreadLocal 的清理、Redis 缓存的适用场景、以及云端设备和本地设备双写时潜在的一致性风险，这些我在做项目时都会重点考虑。
