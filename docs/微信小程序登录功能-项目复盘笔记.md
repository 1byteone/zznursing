## 一、功能概述

### 1.1 业务背景
在养老院管理系统中，需要为老人家属提供微信小程序端访问入口。家属可以通过小程序登录系统，查看老人信息、预约参观等功能。由于小程序端与后台管理端用户体系不同，需要独立实现小程序登录认证机制。

### 1.2 核心功能
| 功能模块 | 描述 |
|---------|------|
| 微信授权登录 | 通过微信code获取openid，实现静默登录 |
| 手机号绑定 | 获取微信绑定的手机号，完善用户信息 |
| JWT Token | 生成token用于后续请求认证 |
| ThreadLocal存储 | 在拦截器中存储用户ID，保证线程隔离 |
| 内存泄漏防护 | 请求结束后清理ThreadLocal，避免内存泄漏 |

### 1.3 技术栈
| 技术 | 用途 |
|------|------|
| 微信开放平台API | 获取openid和手机号 |
| JWT (JJWT) | Token生成与解析 |
| ThreadLocal | 线程内用户信息存储 |
| Spring Interceptor | 请求拦截与认证 |
| Hutool | HTTP请求和JSON处理 |

## 三、核心代码实现

### 3.1 ThreadLocal工具类

**文件路径**：`zzyl-common/src/main/java/com/zzyl/common/utils/UserThreadLocal.java`

```java
@Slf4j
public class UserThreadLocal {

    // 静态final的ThreadLocal，存储用户ID
    private static final ThreadLocal<Long> LOCAL = new ThreadLocal<>();

    // 私有构造器，防止实例化
    private UserThreadLocal() {
    }

    /**
     * 将用户ID放入ThreadLocal
     */
    public static void set(Long authUserInfo) {
        LOCAL.set(authUserInfo);
    }

    /**
     * 从ThreadLocal获取用户ID
     */
    public static Long get() {
        return LOCAL.get();
    }

    /**
     * 清除ThreadLocal中的数据（防止内存泄漏）
     */
    public static void remove() {
        LOCAL.remove();
    }

    /**
     * 获取当前用户ID
     */
    public static Long getUserId() {
        return LOCAL.get();
    }
}
```

**面试要点**：

1. **为什么使用ThreadLocal？**
   - 每个请求在独立线程中处理
   - ThreadLocal保证线程内数据隔离
   - 避免参数层层传递

2. **ThreadLocal原理**：
   - 每个Thread对象内部维护一个ThreadLocalMap
   - Key是ThreadLocal对象，Value是存储的值
   - 不同线程访问同一个ThreadLocal，获取的是各自线程的值

3. **内存泄漏问题**：
   - ThreadLocal的生命周期与线程相同
   - 线程池中的线程会被复用，ThreadLocal中的数据不会自动清理
   - 必须在请求结束后手动调用`remove()`清理

### 3.2 会员拦截器

**文件路径**：`zzyl-framework/src/main/java/com/zzyl/framework/interceptor/MemberInterceptor.java`

```java
@Component
public class MemberInterceptor implements HandlerInterceptor {

    private final TokenService tokenService;

    public MemberInterceptor(TokenService tokenService) {
        this.tokenService = tokenService;
    }

    /**
     * 前置处理：解析Token，存储用户ID到ThreadLocal
     */
    @Override
    public boolean preHandle(HttpServletRequest request,
                            HttpServletResponse response,
                            Object handler) throws Exception {

        // 1. 如果不是Controller层的请求，直接放行
        if (!(handler instanceof HandlerMethod)) {
            return true;
        }

        // 2. 获取header中的token
        String token = request.getHeader("authorization");

        // 3. 如果token为空，响应401
        if (StringUtils.isEmpty(token)) {
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            throw new BaseException("认证失败");
        }

        // 4. 解析token
        Claims claims = tokenService.parseToken(token);
        if (ObjectUtil.isEmpty(claims)) {
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            throw new BaseException("认证失败");
        }

        // 5. 获取token中的用户ID
        Long userId = MapUtil.get(claims, "userId", Long.class);
        if (ObjectUtil.isEmpty(userId)) {
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            throw new BaseException("认证失败");
        }

        // 6. 将用户ID放入ThreadLocal中（核心步骤）
        UserThreadLocal.set(userId);

        return true;
    }

    /**
     * 后置处理：清理ThreadLocal，防止内存泄漏
     */
    @Override
    public void afterCompletion(HttpServletRequest request,
                               HttpServletResponse response,
                               Object handler,
                               Exception ex) throws Exception {
        // 必须清理，防止内存泄漏
        UserThreadLocal.remove();
    }
}
```

**面试要点**：

1. **拦截器执行流程**：
   ```
   请求 → preHandle → Controller → postHandle → afterCompletion
   ```
   - `preHandle`：请求处理前执行，返回true放行
   - `afterCompletion`：请求完成后执行，无论是否异常

2. **为什么在afterCompletion中清理？**
   - 保证无论请求成功或失败，都会清理ThreadLocal
   - 避免线程池复用导致的数据污染
   - 防止内存泄漏

3. **401状态码**：
   - HTTP标准状态码，表示未授权
   - 前端收到401后跳转登录页

### 3.4 微信服务实现

**文件路径**：`zzyl-nursing-platform/src/main/java/com/zzyl/nursing/service/impl/WechatServiceImpl.java`

```java
@Service
public class WechatServiceImpl implements WechatService {

    // 微信API地址
    private static final String REQUEST_URL =
        "https://api.weixin.qq.com/sns/jscode2session?grant_type=authorization_code";

    private static final String TOKEN_URL =
        "https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential";

    private static final String PHONE_REQUEST_URL =
        "https://api.weixin.qq.com/wxa/business/getuserphonenumber?access_token=";

    @Value("${wechat.appId}")
    private String appid;

    @Value("${wechat.appSecret}")
    private String secret;

    /**
     * 获取openid
     */
    @Override
    public String getOpenid(String code) {
        // 1. 封装请求参数
        Map<String, Object> paramMap = getAppConfig();
        paramMap.put("js_code", code);

        // 2. 调用微信API
        String result = HttpUtil.get(REQUEST_URL, paramMap);

        // 3. 解析结果
        JSONObject jsonObject = JSONUtil.parseObj(result);

        // 4. 错误检查
        if (ObjectUtil.isNotEmpty(jsonObject.getInt("errcode"))) {
            throw new RuntimeException(jsonObject.getStr("errmsg"));
        }

        // 5. 返回openid
        return jsonObject.getStr("openid");
    }

    /**
     * 获取手机号
     */
    @Override
    public String getPhone(String detailCode) {
        // 1. 获取access_token
        String token = getToken();

        // 2. 构建请求URL
        String url = PHONE_REQUEST_URL + token;

        // 3. 封装请求参数
        Map<String, Object> paramMap = new HashMap<>();
        paramMap.put("code", detailCode);

        // 4. 发起POST请求
        String result = HttpUtil.post(url, JSONUtil.toJsonStr(paramMap));

        // 5. 解析结果
        JSONObject jsonObject = JSONUtil.parseObj(result);
        if (jsonObject.getInt("errcode") != 0) {
            throw new RuntimeException(jsonObject.getStr("errmsg"));
        }

        // 6. 返回手机号
        return jsonObject.getJSONObject("phone_info").getStr("phoneNumber");
    }

    /**
     * 获取access_token
     */
    private String getToken() {
        Map<String, Object> paramMap = getAppConfig();
        String result = HttpUtil.get(TOKEN_URL, paramMap);
        JSONObject jsonObject = JSONUtil.parseObj(result);

        if (ObjectUtil.isNotEmpty(jsonObject.getInt("errcode"))) {
            throw new RuntimeException(jsonObject.getStr("errmsg"));
        }

        return jsonObject.getStr("access_token");
    }

    /**
     * 封装公共参数
     */
    private Map<String, Object> getAppConfig() {
        Map<String, Object> paramMap = new HashMap<>();
        paramMap.put("appid", appid);
        paramMap.put("secret", secret);
        return paramMap;
    }
}
```

**面试要点**：

1. **微信登录流程**：
   ```
   小程序 wx.login() → code → 后端 → jscode2session → openid
   ```

2. **code的作用**：
   - 临时登录凭证，5分钟有效
   - 只能使用一次
   - 用于换取openid和session_key

3. **openid的作用**：
   - 用户在当前小程序的唯一标识
   - 用于识别用户身份
   - 不同小程序的openid不同

4. **获取手机号流程**：
   ```
   小程序获取phoneCode → 后端获取access_token → 调用getPhoneNumber API → 手机号
   ```

### 3.5 登录业务实现

**文件路径**：`zzyl-nursing-platform/src/main/java/com/zzyl/nursing/service/impl/FamilyMemberServiceImpl.java`

```java
@Service
public class FamilyMemberServiceImpl extends ServiceImpl<FamilyMemberMapper, FamilyMember>
    implements IFamilyMemberService {

    @Autowired
    private WechatService wechatService;

    @Autowired
    private TokenService tokenService;

    // 默认昵称前缀
    static List<String> DEFAULT_NICKNAME_PREFIX = ListUtil.of(
        "生活更美好", "大桔大利", "日富一日", "好柿开花",
        "柿柿如意", "一椰暴富", "大柚所为", "杨梅吐气", "天生荔枝"
    );

    /**
     * 小程序端登录
     */
    @Override
    public LoginVo login(UserLoginRequestDto userLoginRequestDto) {
        // 1. 调用微信API获取openId
        String openId = wechatService.getOpenid(userLoginRequestDto.getCode());

        // 2. 根据openId查询用户
        FamilyMember familyMember = getOne(
            Wrappers.<FamilyMember>lambdaQuery(FamilyMember.class)
                .eq(FamilyMember::getOpenId, openId)
        );

        // 3. 如果用户为空，创建新用户对象
        if (ObjectUtils.isEmpty(familyMember)) {
            familyMember = FamilyMember.builder().openId(openId).build();
        }

        // 4. 调用微信API获取手机号
        String phone = wechatService.getPhone(userLoginRequestDto.getPhoneCode());

        // 5. 保存或更新用户
        saveOrUpdateFamilyMember(familyMember, phone);

        // 6. 生成JWT Token
        Map<String, Object> claims = new HashMap<>();
        claims.put("userId", familyMember.getId());
        claims.put("nickName", familyMember.getName());

        String token = tokenService.createToken(claims);

        // 7. 构建返回对象
        LoginVo loginVo = new LoginVo();
        loginVo.setToken(token);
        loginVo.setNickName(familyMember.getName());

        return loginVo;
    }

    /**
     * 保存或更新用户
     */
    private void saveOrUpdateFamilyMember(FamilyMember member, String phone) {
        // 1. 手机号变化则更新
        if (ObjectUtil.notEqual(phone, member.getPhone())) {
            member.setPhone(phone);
        }

        // 2. 用户已存在，更新
        if (ObjectUtil.isNotEmpty(member.getId())) {
            updateById(member);
            return;
        }

        // 3. 新用户，生成随机昵称
        String nickName = DEFAULT_NICKNAME_PREFIX.get(
            (int)(Math.random() * DEFAULT_NICKNAME_PREFIX.size())
        ) + phone.substring(phone.length() - 4);

        member.setName(nickName);
        save(member);
    }
}
```

**面试要点**：

1. **登录流程设计**：
   - 先获取openid判断用户是否存在
   - 再获取手机号完善用户信息
   - 最后生成token返回

2. **自动注册机制**：
   - 用户不存在时自动创建
   - 生成随机昵称（前缀+手机号后四位）

3. **Token生成**：
   - 使用JWT存储userId和nickName
   - 前端每次请求携带Token

### 3.6 Token服务

**文件路径**：`zzyl-framework/src/main/java/com/zzyl/framework/web/service/TokenService.java`

```java
@Component
public class TokenService {

    @Value("${token.secret}")
    private String secret;

    /**
     * 创建Token（小程序端使用）
     */
    public String createToken(Map<String, Object> claims) {
        String token = Jwts.builder()
                .setClaims(claims)
                .signWith(SignatureAlgorithm.HS512, secret)
                .compact();
        return token;
    }

    /**
     * 解析Token
     */
    public Claims parseToken(String token) {
        return Jwts.parser()
                .setSigningKey(secret)
                .parseClaimsJws(token)
                .getBody();
    }
}
```

**面试要点**：

1. **JWT组成**：
   ```
   Header.Payload.Signature
   ```
   - Header：算法和类型
   - Payload：存储的数据（userId, nickName）
   - Signature：签名，防止篡改

2. **JWT优势**：
   - 无状态，服务端不需要存储
   - 可携带用户信息
   - 跨服务共享

3. **JWT安全问题**：
   - 不要存储敏感信息
   - 设置合理的过期时间
   - 使用HTTPS传输

## 五、ThreadLocal深度解析

### 5.1 ThreadLocal原理图

```
┌─────────────────────────────────────────────────────────────┐
│                        Thread对象                            │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              ThreadLocalMap                          │   │
│  │  ┌─────────────────────────────────────────────┐    │   │
│  │  │  Entry(ThreadLocal key, Object value)       │    │   │
│  │  │  ┌─────────────┐  ┌─────────────────────┐   │    │   │
│  │  │  │ UserThreadLocal │  │ userId = 12345   │   │    │   │
│  │  │  └─────────────┘  └─────────────────────┘   │    │   │
│  │  └─────────────────────────────────────────────┘    │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘

Thread-1: ThreadLocalMap → {UserThreadLocal: 12345}
Thread-2: ThreadLocalMap → {UserThreadLocal: 67890}
Thread-3: ThreadLocalMap → {UserThreadLocal: 11111}
```

### 5.2 内存泄漏问题

**问题原因**：
```
ThreadLocal → ThreadLocalMap → Entry → Value

Entry继承自WeakReference，Key是弱引用
但Value是强引用，不会自动回收

如果线程被线程池复用：
- ThreadLocalMap不会被清理
- Value一直存在
- 导致内存泄漏
```

**解决方案**：
```java
@Override
public void afterCompletion(...) {
    // 必须手动清理
    UserThreadLocal.remove();
}
```

### 5.3 为什么用static final？

```java
private static final ThreadLocal<Long> LOCAL = new ThreadLocal<>();
```

**原因**：
1. **static**：所有实例共享同一个ThreadLocal对象
2. **final**：防止被重新赋值，保证一致性
3. **节省内存**：避免每个实例创建新的ThreadLocal

## 六、面试常见问题

### Q1：ThreadLocal和Synchronized的区别？

**参考回答**：

| 对比项 | ThreadLocal | Synchronized |
|--------|-------------|--------------|
| 目的 | 数据隔离 | 数据共享 |
| 原理 | 线程本地存储 | 锁机制 |
| 场景 | 每个线程独立数据 | 多线程访问共享资源 |
| 性能 | 无锁，性能高 | 有锁，可能阻塞 |

**示例**：
- ThreadLocal：每个用户请求的userId
- Synchronized：多个用户同时修改同一个数据

### Q2：为什么必须调用remove()？

**参考回答**：
```
1. 线程池复用问题：
   - Tomcat使用线程池处理请求
   - 线程处理完请求后不会销毁，而是回到线程池
   - ThreadLocal中的数据不会自动清理

2. 内存泄漏：
   - ThreadLocalMap的Value是强引用
   - 不清理会一直占用内存
   - 大量请求后可能OOM

3. 数据污染：
   - 线程被复用后，可能获取到上一个用户的数据
   - 导致用户A看到用户B的数据（严重安全问题）

解决方案：
- 在拦截器的afterCompletion中调用remove()
- 无论请求成功或失败，都会执行清理
```

### Q3：JWT Token存储在客户端安全吗？

**参考回答**：
```
安全措施：
1. 不要存储敏感信息（密码、身份证等）
2. 设置合理的过期时间
3. 使用HTTPS传输，防止中间人攻击
4. Token存储在localStorage或sessionStorage
5. 重要操作需要二次验证

本项目做法：
- Token只存储userId和nickName
- 不存储敏感信息
- 前端存储在localStorage
```

### Q4：微信登录和传统登录的区别？

**参考回答**：

| 对比项 | 微信登录 | 传统登录 |
|--------|---------|---------|
| 认证方式 | openid + 手机号 | 用户名 + 密码 |
| 用户标识 | openid | 用户名 |
| 自动注册 | 支持 | 不支持 |
| 安全性 | 微信背书，较安全 | 依赖密码强度 |

### Q5：如何处理Token过期？

**参考回答**：
```
当前实现：
- Token未设置过期时间
- 前端判断Token是否存在

改进方案：
1. JWT设置exp字段（过期时间）
2. 拦截器检查过期时间
3. 过期返回401，前端跳转登录
4. 可实现Token刷新机制（refreshToken）
```

### Q6：如何防止Token被盗用？

**参考回答**：
```
防护措施：
1. HTTPS传输加密
2. Token绑定设备信息（User-Agent、IP）
3. Token设置较短有效期
4. 敏感操作二次验证
5. 异常登录检测

本项目：
- 使用HTTPS
- 后续可增加IP绑定
```

### Q7：ThreadLocal在项目中的其他应用？

**参考回答**：
```
常见应用场景：
1. 用户上下文：存储当前用户信息
2. 请求上下文：存储请求相关信息
3. 数据库连接：每个线程独立连接
4. 事务管理：Spring事务使用ThreadLocal
5. 日期格式化：SimpleDateFormat线程不安全

本项目：
- UserThreadLocal：存储用户ID
- 保证多线程下用户数据隔离
```
