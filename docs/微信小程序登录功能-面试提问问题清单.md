# 微信小程序登录功能 - 面试提问问题清单

## 一、业务理解类

### Q1: 请介绍一下微信小程序登录的整体流程？
**考察点**：业务流程理解、系统设计
**参考答案要点**：
- 小程序调用wx.login()获取临时code
- 后端调用jscode2session获取openid
- 根据openid查询/创建用户
- 获取微信绑定的手机号完善信息
- 生成JWT Token返回给前端

### Q2: 微信登录和传统登录有什么区别？
**考察点**：技术对比、设计理解
**参考答案要点**：
- 认证方式：openid + 手机号 vs 用户名 + 密码
- 用户标识：openid vs 用户名
- 自动注册：微信登录支持自动注册
- 安全性：微信背书，较安全

## 二、ThreadLocal核心类

### Q3: 为什么使用ThreadLocal存储用户ID？有什么优势？
**考察点**：ThreadLocal原理、设计模式
**参考答案要点**：
- 每个请求在独立线程中处理
- ThreadLocal保证线程内数据隔离
- 避免参数层层传递
- 方便在任意位置获取用户信息

### Q4: ThreadLocal的原理是什么？请画图说明？
**考察点**：底层原理、深度理解
**参考答案要点**：
- 每个Thread对象内部维护一个ThreadLocalMap
- Key是ThreadLocal对象，Value是存储的值
- 不同线程访问同一个ThreadLocal，获取的是各自线程的值
- ThreadLocalMap是Thread的内部类

### Q5: 为什么必须调用remove()方法？不调用会有什么问题？
**考察点**：内存泄漏、线程池复用
**参考答案要点**：
- Tomcat使用线程池，线程会被复用
- ThreadLocal中的数据不会自动清理
- 导致内存泄漏，大量请求后可能OOM
- 数据污染：用户A可能看到用户B的数据

### Q6: ThreadLocal为什么要用static final修饰？
**考察点**：代码细节、设计理解
**参考答案要点**：
- static：所有实例共享同一个ThreadLocal对象
- final：防止被重新赋值，保证一致性
- 节省内存：避免每个实例创建新的ThreadLocal

## 三、拦截器设计类

### Q7: 拦截器的执行流程是怎样的？preHandle和afterCompletion分别在什么时候执行？
**考察点**：Spring MVC、拦截器原理
**参考答案要点**：
- 执行流程：请求 → preHandle → Controller → postHandle → afterCompletion
- preHandle：请求处理前执行，返回true放行
- afterCompletion：请求完成后执行，无论是否异常

### Q8: 为什么在afterCompletion中清理ThreadLocal？
**考察点**：资源管理、异常处理
**参考答案要点**：
- afterCompletion无论请求成功或失败都会执行
- 保证ThreadLocal一定会被清理
- 避免线程池复用导致的数据污染

### Q9: 拦截器和过滤器有什么区别？
**考察点**：技术对比、Spring架构
**参考答案要点**：
- 拦截器属于Spring MVC，过滤器属于Servlet
- 拦截器在Controller前后执行，过滤器在DispatcherServlet前后
- 拦截器可获取Controller信息，过滤器更底层
- 过滤器适合编码过滤，拦截器适合认证授权

## 四、JWT Token类

### Q10: JWT Token由哪几部分组成？各部分的作用是什么？
**考察点**：JWT原理、安全理解
**参考答案要点**：
- Header：算法和类型
- Payload：存储的数据（userId, nickName）
- Signature：签名，防止篡改

### Q11: JWT Token存储在客户端安全吗？如何增强安全性？
**考察点**：安全意识、防护措施
**参考答案要点**：
- 不要存储敏感信息（密码、身份证等）
- 设置合理的过期时间
- 使用HTTPS传输
- Token绑定设备信息（User-Agent、IP）
- 敏感操作需要二次验证

### Q12: 如何处理Token过期？
**考察点**：系统设计、用户体验
**参考答案要点**：
- JWT设置exp字段（过期时间）
- 拦截器检查过期时间
- 过期返回401，前端跳转登录
- 可实现Token刷新机制（refreshToken）

## 六、深度追问类

### Q16: ThreadLocal和Synchronized的区别？
**考察点**：并发编程、技术对比
**参考答案要点**：
- ThreadLocal：数据隔离，每个线程独立数据
- Synchronized：数据共享，多线程访问共享资源
- ThreadLocal无锁性能高，Synchronized可能阻塞
- ThreadLocal用于用户请求等独立数据，Synchronized用于共享资源保护

### Q17: 如何防止Token被盗用？
**考察点**：安全防护、系统设计
**参考答案要点**：
- HTTPS传输加密
- Token绑定设备信息（User-Agent、IP）
- Token设置较短有效期
- 敏感操作二次验证
- 异常登录检测

### Q18: 新用户自动注册时，昵称是如何生成的？
**考察点**：业务细节、用户体验
**参考答案要点**：
- 随机前缀（如"生活更美好"、"大桔大利"等）
- 加上手机号后四位
- 生成唯一且友好的昵称

**参考答案要点**：
- 用户上下文：存储当前用户信息
- 请求上下文：存储请求相关信息
- 数据库连接：每个线程独立连接
- 事务管理：Spring事务使用ThreadLocal
- 日期格式化：SimpleDateFormat线程不安全
